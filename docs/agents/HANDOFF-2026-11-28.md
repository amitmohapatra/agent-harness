## What changed (all on main) and why

| Change | Why |
|---|---|
| `without=["recall"]`: on-demand memory per agent or run | an agent that searches itself needs only what stands (profile, rules that apply, conversation) |
| One memory status: the harness note replaces the service's status line (`agent.told_once`) | the status was said twice |
| A scheduled run's task and a harness notification go to memory with `origin` schedule / app | they are not the person's words; memory must not learn preferences from them |
| Skills listed even when the app wraps `load_skill`; a loaded skill's tools are offered | a wrapped `load_skill` silently dropped the listing |
| Secrets masked in traces (GitHub, AWS, Slack, Google, Stripe, private keys, URL passwords, labelled values) | credentials inside text reached the tracing backend |
| File writes in the run's own folder do not ask; a file the user names without a place is kept | the earlier pending decisions, applied with the recommended defaults |
| LoCoMo through a harness agent (`benchmark/locomo/`) | to measure attached vs on-demand memory with a real model (not run yet) |
| Two helpers keep `history.recorded` and the masking within the complexity budget | budget test |

## Verified

On main, against memory's main: unit + integration + contract 7,934 passed at 100% line and
branch coverage; matrix 13,045 passed; feature proofs 190 passed; scenarios 406 of 407. The one
failure (20-message burst, function adapter) asked every earlier turn to be in the window; the
rendered window holds 20 messages (10 turns), and with no model summary the older turns were
also dropped from Memories. Memory now leaves a turn out of Memories only when the window or
summary carries it, and the scenario asserts the window's turns (`WINDOW_TURNS`), as scenario
7 already did for a long chat. Requires trellis-memory 0.6.11 (memory's main).

## LoCoMo through the harness, measured

Haiku 5.5 answering and judging, conversations 0-1 (304 questions), strict rules, the
memory repository's scorer (`benchmark/locomo/README.md` for the commands):

| arm | overall | answerable | abstains on adversarial | multi-hop | model calls | cost |
|---|---|---|---|---|---|---|
| no memory (`--arm off`) | 23.4% | 0% | 100% | 0% | 304 | $0.03 |
| memory on demand (`--without recall`) | 73.0% | 77.3% | 59.2% | 53.5% | 685 | $0.49 |
| memory attached (`--arm push`) | 82.6% | 87.1% | 67.6% | 83.7% | 325 | $0.46 |
| memory's direct arm (one context, one call) | 81.9% | 84.1% | 74.6% | 72.1% | - | - |

Attached beats on demand by 10 points, most on multi-hop. The on-demand agent did search on
those (2 searches in 11 of the 20 it got wrong) and answered from part of a list spread over
sessions ("Charlotte's Web" of two books named). Both arms ask the same questions: each run's users and agents
carry its `--out` name, so neither reads the other's recorded answers.
